# Persistent Agents (2.2)

Agent Teams 位于侧栏「定时任务」下方。该版本实现全局持久化 Agent；通信、编排和自动调度不在本次范围内。

## 使用

1. 新建 Agent，在「基本信息」填写名称与简介；在「身份指令」编辑 AGENTS.md，可切换编辑、Markdown 预览及分栏实时预览。
2. 在「工具与技能」勾选工具及已安装 Skill。Skill 支持按名称或用途搜索、刷新，以及显示已选但暂时缺失的条目；加载失败不会清空原配置。
3. 保存后点击「运行」，选择项目目录，输入任务并运行。每次运行创建独立会话，使用 Studio 的默认模型及权限模式。
4. 在「独立记忆」查看、归档该 Agent 的记忆；在「执行记录」进入对应会话查看输出和工具轨迹。
5. 编辑身份与能力后，下次执行加载新配置。删除身份前须停止其执行会话；删除身份及记忆不删除历史会话。

## 数据与执行

数据根目录沿用 `NOVA_CODING_AGENT_DIR`，默认 `~/.nova/agent`。

```
agents/<uuid>/
  profile.json       # 名称、简介、工具与 Skill 名称、时间和运行记录
  AGENTS.md          # 独立身份指令
  memory/            # 复用 Nova Memory 的事实、建议、锁与原子写入
```

工具选择器通过 `list_agent_tools` RPC 读取共享 Agent 运行时的实际工具注册表，包含内置与扩展工具，展示名称与说明。新建 Agent 默认选择运行时当前启用的工具，不在前端维护工具名单或默认工具组合。已有选择不会随目录刷新被覆盖；当前未注册的已选工具会标记为不可用。

Skill 选择器通过 `list_installed_agent_skills` RPC 复用 Nova 的资源发现逻辑，展示全局目录、通用用户技能目录及配置路径中的已安装技能，排除项目局部资源；读取目录信息时不执行扩展代码。

模型认证、模型目录和已安装 Skill 仍由根目录管理。项目上下文来自本次选择的目录，Agent 记忆只有一套全局库，不为项目另建命名空间。

Studio 将身份 ID 经共享 RPC Host 的 `agent_create.persistentAgentId` 传入。Host 返回实际加载的身份 ID，Studio 验证二者一致，防止旧 CLI 静默创建普通会话。开发和打包必须使用包含本次后端修改的 Nova CLI。

会话中保存 `persistent_agent` 元数据；恢复会话、创建新会话时继续加载原身份。工具白名单和 Skill 过滤在执行侧生效。记忆 RPC、内置记忆工具、自动检索、抽取、启动补偿和评审均绑定到身份目录；历史补偿按身份过滤，普通全局记忆也不扫描这些会话。

持久化 Agent 在每个任务回合后排队抽取，至少一条用户消息即可进入抽取流程，继续遵守 Memory 的开关、每日预算、去重、敏感信息过滤及置信度要求。抽取可保存明确的用户偏好，以及有工具证据或用户反馈支持的通用工作经验；不把助手的成功声明当作验证，也不保存临时任务流水账。普通 Nova 会话保持原有用户事实抽取语义。

## 验证边界

本次通过前端类型检查、Rust 存储测试、Nova 检查和相关回归测试。源码 RPC 冒烟覆盖跨项目身份、工具白名单与历史会话恢复；浏览器使用模拟 Tauri 桥接验证页面交互。尚未进行原生 Tauri 窗口及真实模型任务验收。
