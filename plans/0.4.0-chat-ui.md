# v0.4.0 — Chat UI 组件化重构

> 分支：`0.4.0-chat-ui`
> 基于：`0.3.0-sidecar`

---

## 目标

修复消息重复显示 bug，将 AppShell.tsx（456 行单体组件）拆分为独立的聊天 UI 组件，补齐 Markdown 渲染、代码高亮、工具调用卡片等核心对话体验。

AppShell.tsx 把 sidebar、消息列表、输入框全塞在一起。消息只有纯文本气泡，没有 Markdown/代码高亮，工具调用只显示名字没有详情。**存在消息重复 bug。**

## P0 Bug Fix：消息重复显示

### 现象

用户发送一条消息后，界面出现：
- 左侧显示 2 条相同的用户输入（不应该出现，用户输入只应在右侧）
- 左侧显示 2 条相同的 assistant 回复（应该只显示 1 条）

### 数据流追踪

```
用户输入 → addUserMessage() → messages 加 1 条 user（正确）
         → sendPrompt() → agent 处理
         → agent stdout JSONL → Rust 解析 → emit("agent-event")
         → handleAgentEvent() → applyEvent()
```

`applyEvent` 中有 **两个分支会添加 assistant 消息**：

1. **`message_end`**（第 165-181 行）：从 `event.message` 提取文本，作为 assistant 消息加入
2. **`agent_settled`**（第 214-237 行）：如果 `streamingText` 非空，flush 为 assistant 消息

### 可能根因（需 debug log 验证）

| 假设 | 说明 | 验证方式 |
|------|------|----------|
| A. Agent 回显用户输入 | `message_end.message.content` 包含 user + assistant 混合内容 | 打印 `event.message` 完整结构 |
| B. 双重添加 | `message_end` 加了完整文本后，`agent_settled` 又 flush 了一遍 `streamingText` | 检查 `streamingText` 在 `message_end` 后是否被清空 |
| C. Agent 发送多轮 message_end | 一轮对话中 agent 发了两次 `message_end` 事件 | 在 Rust stdout reader 打印每个事件的 type |

### 修复方案

**Step 1：加 debug log 确认根因**

在 `applyEvent` 的 `message_end` 分支加 log：

```typescript
case "message_end": {
  console.log("[message_end] full message:", JSON.stringify(event.message));
  const text = extractAssistantText(event.message);
  console.log("[message_end] extracted text:", text?.substring(0, 100));
  // ...
}
```

**Step 2：根据根因修复**

- **如果是 A**（message.content 混合了 user 内容）：在 `extractAssistantText` 中过滤 role，只提取 `role === "assistant"` 的内容块
- **如果是 B**（双重添加）：`message_end` 已经添加了消息，`agent_settled` 中不再重复添加，只做状态清理
- **如果是 C**（多轮 message_end）：在 store 中加去重逻辑，用消息内容 hash 或 message ID 去重

**Step 3：清理 user 消息在左侧的显示**

当前 `message_end` 不区分 role，如果 `message` 对象中包含 user 消息，需要过滤掉。`extractAssistantText` 应只提取 `role === "assistant"` 的内容块。

### 涉及文件

- `src/stores/agent-store.ts` — `applyEvent` 的 `message_end` 和 `agent_settled` 分支
- `src/lib/event-parser.ts` — `extractAssistantText` 函数（可能需要改为只提取 assistant 内容）

## 组件拆分计划

### 1. `ChatMessage.tsx` — 消息气泡

**从 AppShell 中提取**（第 206-258 行的消息渲染逻辑）

- 用户消息：右对齐，渐变背景
- 助手消息：左对齐，浅色背景，支持 Markdown 渲染
- 使用 `react-markdown` 渲染助手消息内容
- 用 `rehype-raw` 支持 HTML（agent 输出可能包含）
- 代码块用 `Shiki` 做语法高亮（lazy load，只渲染可见区域）
- 内联代码用 `react-markdown` 默认的 `<code>` 样式

**依赖：** `react-markdown`, `shiki`, `rehype-raw`

### 2. `CodeBlock.tsx` — 代码块

- Shiki 语法高亮，支持主流语言自动检测
- 顶部显示语言标签 + 文件名（如果有）
- 右上角复制按钮（clipboard API）
- 暗色主题配色（配合整体暗色 UI）
- 长代码块可折叠（默认显示前 30 行）

### 3. `StreamingText.tsx` — 流式文本

**从 AppShell 中提取**（第 225-232 行）

- 打字机效果：逐字/逐 token 出现
- 闪烁光标（`animate-pulse`）
- 流式结束后光标消失，内容转为普通 `ChatMessage`
- 支持 Markdown 实时渲染（边生成边渲染）

### 4. `ToolCallCard.tsx` — 工具调用卡片

**从 AppShell 中提取**（第 235-257 行）

按工具类型分样式：

| 工具 | 图标 | 样式 |
|------|------|------|
| `bash` | Terminal | 深色代码块，显示命令 |
| `read` | FileText | 文件路径 + 行号范围 |
| `edit` | Pencil | 左右 diff 视图 |
| `write` | FilePlus | 文件路径 + 内容预览 |
| `grep` | Search | 搜索模式 + 匹配结果 |
| `glob` | FolderOpen | 文件路径模式 |

公共状态指示器：
- running: 蓝色 spinner + 脉冲动画
- done: 绿色对勾
- error: 红色叉号

点击可展开/收起详情（默认收起，只显示工具名和状态）

### 5. `AgentStatusBar.tsx` — 状态栏

- 左侧：当前模型名称（如 `claude-opus-4-8`）
- 右侧：token 用量（input/output）、对话轮次、耗时
- 流式输出时显示实时 token/s
- 状态：idle / streaming / error + 颜色指示

### 6. `PromptInput.tsx` — 输入框

**从 AppShell 中提取**（第 263-449 行）

- 多行 textarea，自动撑高（已实现，提取出来）
- Shift+Enter 换行，Enter 发送
- 底部工具栏：附件、模型选择、thinking level、发送/停止
- 流式中：发送按钮变为停止按钮（红色 Square）
- 空状态：居中大输入框；有消息后：底部固定窄输入框

### 7. `AgentPanel.tsx` — Agent 面板

组装以上组件：

```
┌─────────────────────────────────┐
│  AgentStatusBar                 │
├─────────────────────────────────┤
│                                 │
│  ChatMessage (user)             │
│  ChatMessage (assistant)        │
│  ToolCallCard (bash)            │
│  ToolCallCard (read)            │
│  StreamingText                  │
│                                 │
├─────────────────────────────────┤
│  PromptInput                    │
└─────────────────────────────────┘
```

- 消息列表自动滚动到底部（新消息 / 流式输出时）
- 手动向上滚动时暂停自动滚动，滚到底部恢复
- 空状态显示品牌标语（从 AppShell 移入）
